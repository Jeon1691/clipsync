# ClipSync v0.1.17

This release strengthens webhook destination checks and separates stored
credentials from general configuration and room metadata. It also adds the
implementation and evidence needed to assess every OpenSSF Best Practices
Silver/Gold criterion accurately; those badges are not yet earned.

## Security fixes

- Webhooks now reject nonpublic IPv4/IPv6 destinations after DNS resolution,
  including mixed public/private answers, and connect only to the validated
  addresses. Redirects and inherited proxy routing are disabled for webhook
  delivery. This closes hostname/DNS and IPv6 paths around the previous
  literal-address blocklist. Ordinary public HTTP(S) webhooks remain supported.
- Device tokens and webhook credentials move to separate private files. New
  state/config and CLI JSON omit their secret fields. Legacy migration persists
  credentials before atomically replacing metadata; missing, empty or unwritable
  credentials fail without resetting the user's configuration. Unix writes also
  sync the parent directory before the legacy copy is removed.
- Public initialization now propagates invalid configuration/migration errors
  instead of replacing the file with defaults.

These findings were identified during the project's AI-assisted source/security
review. Regression tests cover the original failures, migration/error paths,
address validation, DNS pinning and redirect refusal. No independent audit is
claimed.

## Quality and verification

- Enforce compiler/Clippy warnings as errors with practical cleanup and narrowly
  documented public-layout exceptions; preserve native clipboard, accessibility
  and binding behavior.
- Add full-workspace line/region/branch coverage reports, AEAD property fuzzing
  with AddressSanitizer, native macOS clipboard/daemon sanitizer testing and
  source copyright/SPDX checks.
- Document governance, conduct, a one-year roadmap, review/security-response
  processes, architecture, security assurance and all higher-tier criteria.
  Publish source-tag signing keys/instructions and actual binary-hardening
  evidence. Preserve requested debug information in the local packaging helper.

## Upgrade notes

Update clients together and stop the daemon before replacing an active binary.
Back up the complete private application data directory before upgrading.
Loading a legacy room/config automatically migrates its credentials; v0.1.16
and older cannot read that new layout. Re-pair if rolling back rather than
running an old binary against migrated data. JSON consumers must allow omission
of `device_token` and webhook `secret` fields; these are intentional redactions.

Self-hosted relay operators must rebuild/redeploy to receive the webhook fix.
Webhook endpoints that resolve to private, special-use or mixed public/private
addresses are intentionally rejected, and a webhook relying on an environment
proxy must be moved to a directly reachable public endpoint. Public relay
deployments still require correctly configured TLS termination and firewalling.

Payload forward secrecy and automatic membership-driven room-key rotation are
unchanged; re-pairing replaces retained keys. Coverage thresholds, reproducible
archives, actual succession and independent human-review history remain
separate outstanding requirements in the criterion register.
