# ClipSync v0.1.18

This release fixes mobile initialization error handling and adds verified relay
container distribution and interoperable release provenance.

## Fixes and verification

- Mobile initialization now reports invalid configuration or credential migration
  errors to its caller. It previously returned an application object after
  ignoring that failure. Regression tests exercise the original failure.
- Enforce at least 80% product line and region coverage across all twelve crates
  and protect regressions for more than half of the recorded historical fixes.
  Native clipboard sanitizer and all-platform CI remain enabled. The project has
  earned the OpenSSF Best Practices Silver badge.
- Export the original signed DSSE envelope as `.intoto.jsonl` alongside each
  Sigstore bundle. Export requires verification of the archive digest, workflow,
  source tag and commit. Publication verifies the complete uploaded asset set in
  a draft before making the release public and refuses to replace published
  assets.
- Publish tested native amd64 and arm64 relay images at
  `ghcr.io/jeon1691/clipsync-relay:v0.1.18`. The runtime uses an unprivileged UID,
  supports a read-only filesystem, and includes signed OCI index provenance.
  Version tags are published only after provenance verification.

## Upgrade notes

The Rust minimum version remains 1.88. Client configuration and the relay's
existing HTTP/TLS-proxy deployment are compatible with v0.1.17. Container users
must follow the TLS termination and private configuration guidance in
[self-hosting](../self-hosting.md); the container does not configure a public
reverse proxy or update an existing server automatically.

The storage migration notes in [v0.1.17](v0.1.17.md) still apply when upgrading
older clients. Do not run an older binary against already migrated private data.
