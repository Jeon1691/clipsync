# ClipSync v0.2.0

This release makes relay encryption mandatory by default, replaces unmaintained
dependency chains, and supplies a portable Linux reproducibility procedure.

## Breaking deployment and build changes

- The relay refuses to listen without a matching TLS certificate/key pair.
  Configure `CLIPSYNC_RELAY_TLS_CERT_FILE`, `CLIPSYNC_RELAY_TLS_KEY_FILE` and an
  HTTPS public URL for direct HTTPS/WSS. TLS 1.2 and 1.3 are supported. Existing
  reverse-proxy and local development deployments must explicitly set
  `CLIPSYNC_RELAY_ALLOW_HTTP=true`; retain TLS termination and private upstream
  networking. See [self-hosting](../self-hosting.md) before upgrading a relay.
- `CLIPSYNC_RELAY_TOKEN_SECRET_FILE` can read exact secret bytes from a private
  mounted file. It cannot be combined with `CLIPSYNC_RELAY_TOKEN_SECRET`, even
  if that environment variable is empty. Preserve the existing secret bytes
  during migration to retain valid tokens. The documented container configuration
  uses a non-root reader group and read-only credential mounts.
- Source builds now require **Rust 1.95 or later**. Linux desktop builds require
  Fontconfig and FreeType development packages; installations need their runtime
  libraries and an installed font. Packaged CLI/relay users do not need a Rust
  compiler or the desktop's native dependencies.
- Mobile consumers must regenerate Swift/Kotlin bindings with this checkout's
  UniFFI 0.32.2 and rebuild the native library. Old generated 0.29 bindings cannot
  be mixed with the new library. Separate iOS/Android app deployment is an
  operator task.

## Revocation correction

Revoking a device now closes its already authenticated relay connection before
discarding the sender. Rejected member handshakes are validated before online
registration. Regression tests verify actual socket closure, blocked sends and
reconnection, persisted revocation and continued owner operation. Update relay
servers to receive this correction. Revocation still does not rotate the room
epoch key automatically; re-pair to replace retained payload keys.

## Dependencies and verification

Eframe 0.37 and UniFFI 0.32.2 replace the old GUI and binding chains. Native
accessibility, both renderers, fonts, clipboard support, X11 and Wayland remain
enabled. Seven documented ClipSync-maintained compatibility patches migrate the
remaining parser and D-Bus APIs to maintained implementations. They preserve
upstream licenses, source hashes and complete local diffs; they require ongoing
maintenance rather than advisory ignores. See [migration evidence](../dependency-migration.md).

The Linux reconstruction procedure freezes the base image, native packages and
Rust compiler, rebuilds in two independently recreated environments without
shared build objects, and compares all six workspace outputs. Published CI
results establish the measured scope; release archive metadata and other
platforms are separate claims. See [build instructions](../builds.md).

The six-digit pairing protocol and stored-key format are retained. Pairing
assumes a trusted relay operator; the clarified assurance case does not claim
confidentiality against a malicious service that generates the pairing password.
Back up private application data and review the v0.1.17 storage migration notes
before updating older clients.
