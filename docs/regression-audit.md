## Scope and counting rules

- Window:2026-05-15 through2026-11-15. The repository began2026-09-16, so its complete development history is within the window.
- Baseline: actual default-branch merge639000d60f1af1cc856fe20c61b60c84f9b2ab7b,61 non-merge commits. Local `refs/heads/master` is stale at02da013, so auditing that local ref alone would omit the November fixes. All61 baseline commits plus all5 PR16 commits through3faac58836d94457c16e890f4d1380151236e5ea were classified; the manifest below makes exclusions reviewable.
- Unit: one distinct corrected failure/security invariant, with a separate row for a materially independent failure path/root cause. Multiple input strings, aliases, package paths, tests, release bumps, and merge commits do not increase the defect count. Successive corporate-CA fixes are grouped; the three emSign advisories sharingCVE-2026-111943 are one defect.
- Main broad denominator includes runtime, security, upstream vulnerability, build, packaging, and CI corrections. Separate rates expose the effect of scope instead of silently excluding weak areas. Pure feature additions, policy additions, documentation refreshes, release bumps, equivalent lint/style cleanup, and additional tests of already-correct behavior are excluded consistently.
- A Yes needs an added test or extended test case that asserts the corrected behavior. Tests added later in the six-month window may count when they specifically exercise the defect. A positive smoke test, whole-workspace build, current scan, or nearby fixture is not automatically a focused regression. No includes unproven/ambiguous coverage; it does not mean the implementation is necessarily wrong.
- One existing Cellar-path fixture was added for the original Cellar defect and later exercised on Windows. It is counted for the distinct backslash bug because that host renders the exact failing path; this is the most favorable reasonable interpretation. Requiring a new fixture specifically at that later fix would reduce coverage by one, never improve the outcome.
- The candidate's new migration safeguards are grouped with the actual credential separation/root config-loss issues. Each preventive test case is not treated as another historical bug. Findings discovered during PR16 are included, even before a release; release status is a separate question.
- This is a source-based self-assessment worksheet, not an official project defect taxonomy imposed by OpenSSF. Reasonable regrouping is possible. The row-level evidence is the basis for a claim, and uncertain cases must not be rounded into Met.

## Important evidence qualifications

- **Compose public key:** new unset/empty-env tests do not load Docker Compose. The old unset-env path already generated a random key. Reintroducing the shared Compose key would not fail those tests, so that deployment defect remainsNo. The separate empty/short explicit-key validation bug is covered.
- **Native pasteboard:** the current tests prove staged image file availability, JPEG→PNG representation, and path/data round trips. They do not perform Finder paste into the focused folder, and they do not publish a legacy filename-list-only clipboard fixture without modern file URLs. Those specific historical defects remainNo.
- **Resource limits:** the one expired-transfer test does not assert the32 concurrent transfer limit. Small valid formats do not assert allocation caps, duplicate manifests, oversized chunk counts, cumulative byte bounds, or excessive commit payload/count. Those remain separate unproven invariants.
- **Secrets:** final0600 permission assertions do not reproduce the old create/write-before-chmod window; the old code also ended at0600. No partial-write fault injection proves old-secret preservation. These remainNo even though the new implementation is stronger.
- **TLS/proxy:** no controlled TLS server/private-root/proxy fixture was found. Generic pairing against loopbackHTTP cannot regress HTTPS certificate policy or macOS proxy handling.
- **Dependency remediation:** the upstream advisory database identifies12 distinct corrected vulnerabilities after deduplicatingCVE aliases. These are fixed dependencies, not12 newly added project regression fixtures. `cargo audit` is monitored and valuable, but routine database lookup alone is not counted as adding a focused reproducer to the project's test suite.
